# SSH MVP 实现审查与修复（2026-09-08）

## 审查结论与范围

依据总体设计及阶段 1 进度文档审查。当前采用 React → Runner API → RunManager → SSH/SFTP 的简化分层，适合 SSH-only MVP；无需为了尚未实现的串口、Managed Runtime 或 Artifact 提前拆分大量空模块。

原实现存在影响运行可靠性、输出完整性和文件边界的缺陷，已直接修复。以下记录描述本次修复后的行为，阶段 1 文档中的包装命令和状态流程是此前实现的快照。

## 已修复问题

| 优先级 | 原问题及影响 | 修复 |
|---|---|---|
| P1 | 同步 Tauri command 调用 `tokio::spawn` 依赖当前线程已进入 Tokio runtime，GUI 启动任务可能 panic | RunManager 使用 Tauri runtime 调度，CLI 同样可用 |
| P1 | 超时后过期 timer 始终 ready，事件循环持续空转；控制通道关闭后也会重复 close | 超时分支在进入停止流程后禁用；接收端关闭即退出，ProcessSession 析构终止后台任务 |
| P1 | 忽略 PTY/exec 请求失败；收到 EOF 立即 close，可能丢失晚到的退出码；断线被记为 exited | 等待协议确认并保留确认前输出；EOF 仅表示输出结束；没有 exit-status/exit-signal 的关闭记为 failed |
| P1 | PID 解析使用有损 UTF-8 的偏移切割原始字节，丢弃标记前输出，短输出可能永远不转发 | 每个 Run 使用唯一 marker；按字节流解析，保留前后内容、跨包 CRLF 和未完成数据 |
| P1 | env 键未校验，command 模式完全忽略 env；入口可越过工作区或被解释成命令行选项 | 后端校验 env、参数、工作区和入口；统一 export；入口规范为 `./relative/path` |
| P1 | 递归同步缺少链接边界保护，可能上传工作区外文件或递归成环；SFTP 写入确认未等待 | 跳过符号链接、拒绝重定向目录边界；检查 mkdir 失败；等待 SFTP shutdown 确认全部写入 |
| P1 | 每次连接持有独立 TOFU 快照，并发连接覆盖信任记录；损坏 JSON 被当成首次连接 | 进程内串行读/校验/写，同一连接重新读取最新记录；读取或解析失败时拒绝信任 |
| P2 | preparing/syncing 的停止需等待连接或同步完成，状态还可能从 stopping 回退到 running | 连接和同步支持取消；新增 starting 状态，仅确认 spawn 后 running；stopping 不再回退 |
| P2 | 终态通知早于 history 更新；移除句柄后 get_run_status 无法查询完成任务 | 先写入历史再通知，状态查询回退到历史；使用完整 UUID，加载历史也限制 200 条 |
| P2 | 包装脚本使用可预测的 `/tmp` 文件名 | 使用 `mktemp`、`umask 077` 和退出清理 trap，检查文件创建及解码失败 |
| P2 | 无扩展名文件未按文档规范化，简单扩展名判断又可能损坏二进制文件 | 无扩展名文本支持 CRLF→LF；含 NUL 或非 UTF-8 的数据保持原字节 |
| P2 | 控制台在 StrictMode 重挂载时未释放终端且丢失 resize 监听；pipe 的 Ctrl+C 只发送普通字节 | 完整释放终端；进入 running/切换 Run 后同步尺寸；Ctrl+C 走 Stop 升级流程，选区时复制 |
| P2 | 输出缓冲无限增长，切换工作区后仍可能使用旧入口，CLI 空参数越界 | 每个 Run 保留最近 2 MiB/4096 块输出，用绝对序号回放；清除旧入口；修复空参数处理 |

## 验证

- Rust 单元测试：PID 任意分包/非 UTF-8/短输出、命令和路径校验、env 引号、历史状态、TOFU 过期快照与损坏配置、文本与二进制同步转换。
- 本地模拟 SSH 服务：拒绝 exec、拒绝 PTY、确认前输出以及 EOF 后延迟 exit-status、无退出状态关闭、超时升级停止。测试仅监听 `127.0.0.1`，不访问实际设备或用户 SSH 配置。
- 前端测试：输出缓冲上限和回放序号、并行 Run 输出隔离和快照不可变、终态历史去重。
- 验证命令：`cargo test --offline`（src-tauri 目录）、`cargo fmt --all -- --check`、`npm test`、`npm run build`。

## 保留的阶段边界与限制

- 串口、Node、venv、Managed Runtime、Artifact、Monaco/保存仍属于后续工作。当前 Runtime 选择直接位于命令构造中，尚无独立 provider trait；增加第二种 Runtime provider 或 transport 时再抽取接口。
- 密码仍按阶段 1 方案明文保存在 devices.json，尚未迁移系统凭据库。
- 远程 workspace 仍按阶段 1 策略保留，未增加自动删除，避免删除用户尚未下载的产物。
- PTY 下复杂进程树仍依赖 Ctrl+C 与现有 pkill 兜底；本地模拟服务不能证明实际 Linux 上的进程树、PTY 交互及 SFTP 行为，需要设备回归。此次未连接文档中的实际测试设备。
- 历史 JSON 仅保存状态，输出只保存在本次前端会话内；已截断的输出和重启后的输出无法恢复。
- TOFU 锁覆盖同一应用进程内的连接；多个应用实例共享配置文件时仍需后续引入文件锁或数据库。
