# 2026-09-12 架构审查修复

本记录覆盖代码审查发现的六项缺陷，以及相关传输接口、工作区同步与前端订阅优化。

## 运行与编辑行为

- SSH 包装器以前台方式执行工作负载，避免非交互 shell 后台任务继承忽略 SIGINT/SIGQUIT。PID 标记由工作负载 shell 自身输出；临时脚本打开后立即删除。PTY 保留控制终端；Pipe 使用 `setsid -w`，即使 setsid 需要 fork，也等待并返回工作负载退出码。
- SSH Pipe 的 INT、TERM、KILL 都按实际 PID 对应的进程组发送；早于 PID 标记的 Stop 会等待标记后发送 INT。PTY 的第一阶段仍通过终端发送 Ctrl+C。设备需要支持 `setsid -w` 才能使用 SSH Pipe。
- 历史面板单独显示运行中任务，并提供选择与 Stop。运行工具栏也提供运行中任务选择器。查看已完成历史不会使仍在运行的任务失去操作入口。
- 初始化与刷新同时读取运行中任务和历史；读取期间收到的新状态不会被旧快照覆盖。
- 文件/工作区选择一旦取代旧读取，就接管 loading 状态的清理。取消新选择后，旧读取结果不再覆盖内容，编辑与保存可以继续。
- 运行草稿（模式、入口、命令、参数、控制台模式、超时）位于共享 store。隐藏/显示面板及重置布局保留草稿；切换工作区清除入口。草稿仅保留在当前应用会话，不写入磁盘。

## 有界输出链路

1. SSH 会话到 RunManager 使用 64 项有界队列。请求确认前的暂存队列同样有数量与字节限制。
2. RunManager 输出按最多 16 KiB 原始字节分块并进行 base64 编码。事件保留窗口为 256 项，超出窗口淘汰旧事件。
3. 桌面端通过 `drain_run_events` 按批拉取，每批最多 64 项，前一批完成后约 33 ms 再请求下一批。同一 WebView 只有一条正在处理的拉取链，不再向 WebView 无限推送 `run-event`。
4. 接收方落后时返回明确的 `resync` 事件并附当前状态快照。界面清除跨越缺口的旧字节片段、标记输出缺失并重新同步状态，防止把缺口两端的 UTF-8 或 ANSI 序列错误拼接。旧状态不能覆盖新的终态。
5. 前端维持单任务 2 MiB / 4096 块、所有任务合计 16 MiB 的缓存预算。优先释放较旧已完成任务输出，再处理运行中任务，当前选中任务最后截断。历史淘汰时释放无关状态和缓存；当前选中项可保留到切换选择。
6. xterm 同时只接收一次尚未确认解析完成的写入，后续字节留在有界 store 中。任务切换在前次写入完成后重置终端，防止旧任务尾部混入新任务。

输出溢出只影响控制台保留内容，不作为工作负载失败或成功的判断依据。历史仍只保存状态，不提供完整日志落盘。CLI 使用相同有界事件窗口，落后时向 stderr 提示并重新查询任务状态。

## 共用架构与限制

- `process.rs` 定义运行状态枚举、传输进度事件、完成结果、停止原因和能力声明。Serial/WSL 共用停止请求转发及结果转换；各传输继续保留自身的完成确认与升级停止协议。
- `workspace_upload.rs` 共用本地遍历、路径/类型检查、有界读取和文本换行规范化。Serial/WSL 继续在远端操作前构建快照；SSH 只保存文件清单，每次在 blocking 线程读取一个有界文件，按 64 KiB 块发送 SFTP。
- 文本判定使用文件名，避免带点目录下的无扩展名文本未被正确规范化。非 UTF-8 或含 NUL 的二进制数据在 SSH/WSL 中保持原样。
- 所有传输跳过 `.git`、`.hg`、`.svn`。Serial/WSL 拒绝链接；SSH 继续跳过符号链接。三者拒绝特殊文件、重定向路径及无效文件名。

| 传输 | 单文件 | 工作区总量 | 条目数 | 相对路径 UTF-8 字节数 |
|---|---:|---:|---:|---:|
| Serial | 1 MiB | 8 MiB | 1024 | 512 |
| WSL | 16 MiB | 64 MiB | 4096 | 1024 |
| SSH | 64 MiB | 256 MiB | 4096 | 1024 |

Serial 仍仅接受无 NUL 的 UTF-8 文本。SSH 新增上述限额，并拒绝特殊文件；远程文件保留 Unix 权限，在 Windows 上传时 `.sh` 使用 0700、其他文件使用 0600。RunRequest 序列化后限制 64 KiB，同时最多运行 32 个任务。

前端使用字段选择器订阅状态，输出批量更新 store；单纯输出更新不会替换运行元数据对象或触发设备栏、工作区、历史列表的无关重绘。

## 回归验证

新增自动化覆盖：前台包装器 SIGINT 与用户清理处理、stdin/实际 PID/退出码/临时文件清理、事件溢出后终态恢复、共享工作区限额和文件增长、取消文件切换竞态、运行中任务操作入口、运行草稿、历史淘汰与全局缓存预算、初始快照竞态、输出批量更新，以及缓慢终端与任务切换。

执行 Rust 全目标离线测试、前端测试、前端构建、Rust 格式检查及 `git diff --check`。Linux 平台额外验证 setsid 进程组和退出码。Windows 的 Git Bash 可验证前台 shell 的信号行为，但不含 setsid；此项需要 Linux 或实际 SSH 设备回归。WSL 集成测试仍按默认策略跳过，串口与 SSH 硬件验证未执行。
