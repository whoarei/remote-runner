# 00016 关闭当前文件

日期：2026-09-12
状态：已实现

## 背景

~~编辑器一次只打开一个文件（00006），但一直没有显式的关闭入口~~（00017 已改为
多标签，关闭按钮移入标签内，紧贴文件名）。想回到空态只能切换工作区，
或删除该文件（00010）。用户只想收起当前文件、用命令模式运行时没有直接路径。

目标：

1. 编辑器标题条与「文件」菜单提供「关闭文件」，回到未打开文件的空态。
2. 未保存修改走既有的保存 / 放弃 / 取消确认（`confirmUnsaved`），不丢内容。
3. 关闭不影响工作区、入口草稿与运行历史。

## 非目标

- 不做多标签和「全部关闭」；关闭粒度就是当前打开的唯一文件。
- 不清除 `runDraft.entry`：关闭不是删除，入口草稿继续指向该文件（删除才清空，
  见 00010）。

## 设计

### store（`src/store.ts`）

新增 `closeFile()`（00017 起为 `closeFile(name?)`，关闭指定标签并激活相邻标签）：

- 无打开文件，或 `loading` / `saving` / `starting` / `guarding` 期间直接忽略
  （与 `reloadFile` 同一组忙时守卫；`confirmUnsaved` 内部也有兜底）。
- 有未保存修改时复用 `confirmUnsaved()`：取消保留现状；保存先写盘成功才关闭；
  放弃直接关闭。
- 关闭时清空 `openFile` / `fileContent` / `savedContent` / `revision` /
  `editorError` / `conflict`，并递增 `documentGeneration`（与切换工作区、
  删除文件的关闭路径一致）。已关闭的空态下残留的错误横幅一并清掉。

### 界面

- `Editor.tsx`：~~标题条保存按钮右侧加「×」关闭按钮~~（00017 起改为标签内的
  × 按钮，紧贴文件名），`locked`（loading / starting / guarding）或保存中禁用；
  编辑区折叠时标签条保持可见，关闭按钮同样可用。
- `MenuBar.tsx`：「文件」菜单在「保存文件」后加「关闭文件」，无打开文件或
  文件操作忙时禁用（00017 起关闭活动标签）。

## 测试

- `tests/store.test.ts`：忙时拒绝关闭；取消保留缓冲区；选「保存」先写盘再
  关闭；选「放弃」直接关闭并清空错误状态；已关闭后重复调用为空操作。
- 验证：`npm test`、`npm run build`、`git diff --check`。

## 风险与限制

- 关闭期间任务准备 / 同步 / 停止（`uploadBusy`）不额外拦截：此时文件已保存
  或用户选了放弃，运行使用的是启动时固定的工作区快照，关闭编辑器不影响
  进行中的任务。
- 关闭后再次打开同一文件走正常读取路径（最新磁盘内容与 revision），
  不存在缓存复用问题。
