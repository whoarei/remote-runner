# 00017 多标签文件编辑区

日期：2026-09-12
状态：已实现

## 背景

编辑区一直只能打开一个文件（00006 首版取舍）。00016 加的关闭按钮位于标题条右端，
离文件名很远；同时「改工具模块 + 改入口脚本一起跑」的工作流需要在文件间来回
切换，每次都要重新读盘。

目标：

1. 编辑区改为标签条：标签内显示文件名、脏标记 ● 和关闭按钮 ×，关闭入口紧贴
   文件名。
2. 每个标签独立的 CodeMirror 实例保持挂载，撤销历史、滚动位置、选区在标签间
   切换后不丢失。
3. 「运行」前保存所有脏标签（00006 原则：任何未保存修改都可能是被 import 的
   模块），任一保存失败则不启动。

## 非目标

- 不做标签拖拽排序、跨窗口拖动、分栏编辑。
- 标签不持久化，重启后回到空态（与之前单文件行为一致）。
- 不做「全部保存 / 全部关闭」菜单项。

## 设计

### 数据模型（`src/editorDocument.ts` / `src/store.ts`）

```ts
interface EditorTab {
  name: string;            // 工作区相对路径，即标签身份
  fileContent: string;     // 当前缓冲
  savedContent: string;    // 上次读取/保存基线
  revision: string;        // 乐观并发令牌
  eol: "lf" | "crlf"; bom: boolean;
  language: EditorLanguage;
  conflict: boolean;
  generation: number;      // 文档代次：重读 / 重新打开时 remount 该标签的编辑器
}
```

store 以 `openTabs: EditorTab[]` + `activeFile: string | null` 取代原单文档字段
（`openFile / fileContent / savedContent / revision / eol / bom / language /
conflict / documentGeneration`）。`loading / saving / starting / guarding /
editorError / changePrompt` 保持全局单飞语义不变。

`dirtyDocument` 拆为 `dirtyTab(tab)` 与 `anyDirty(state)`；窗口关闭守卫、标题栏
脏点、更新安装前检查均改用 `anyDirty`。

### store 行为

- `openWorkspaceFile(name)`：已在标签中仅激活不重读；否则读盘成功后追加标签并
  激活。**打开不再触发未保存确认**（标签互不覆盖），`loadSequence` 继续作废
  迟到的读响应；成功后自动展开折叠的编辑区（沿用 00015）。
- `activateFile(name)`：无守卫切换活动标签。
- `closeFile(name?)`：关闭指定标签（默认活动）。忙时（loading / saving /
  starting / guarding）拒绝；脏标签复用 `confirmUnsaved`（保存 / 放弃 / 取消，
  对话框已带文件名）。关闭后激活相邻标签（优先右侧，再左侧）。
- `editContent(name, content)`：按标签名写入（编辑器实例持有自己的名字，
  不依赖活动态，避免激活竞态写错标签）。
- `saveFile(name?)`：保存指定标签（默认活动）；响应按 `name + generation`
  校验后才更新基线，保存期间继续输入仍标为未保存（同 00006）。
- `saveAllDirty()`：按打开顺序串行保存所有脏标签，任一失败 / 冲突即中止并
  返回 false。`startRun` 改用它；保存全部通过且不再有任何脏标签才启动。
- `confirmAllUnsaved()`：对脏标签逐个串行 `confirmUnsaved`，供窗口关闭、
  切换工作区复用。
- `reloadFile()`：重读活动标签（确认丢弃后），只递增该标签的 generation。
- `setWorkspaceDir`：先 `confirmAllUnsaved`，通过后清空全部标签。
- `renameWorkspaceEntry`：映射所有落在子树内的标签的 `name` / `language`
  （活动态、`runDraft.entry` 沿用现逻辑）。
- `deleteWorkspaceEntry`：对子树内所有脏标签逐个确认；删除后移除这些标签，
  活动标签被移除时落到相邻标签。

### 界面（`src/components/Editor.tsx`）

```
.editor
├─ .editor-tabs    [▾折叠] [main.py ● ×] [utils.sh ×] …   ← 有标签时渲染
├─ .editor-body    每标签一个 CodeEditor（key=name:generation，非活动 display:none）
└─ .editor-status  保存入口（有修改时显示可点击「保存」，否则「已保存」）+ 语言选择
                   与光标 / 编码状态（靠右），均跟随活动标签
```

- 标签条：点击激活；× 关闭该标签（带未保存确认）；活动标签高亮；溢出横向滚动。
- 每个标签的 CodeMirror 实例保持挂载、仅 CSS 隐藏（同终端折叠的做法），撤销
  历史 / 滚动 / 选区天然保留。
- 折叠 chevron 移到标签条左端（00015 的 `.editor-title` 拆分）：折叠时只保留
  标签条，激活或打开标签自动展开。
- 无独立工具条：保存功能以简洁形式并入状态栏——有未保存修改时显示可点击的
  「保存」（等价 Ctrl+S），保存后或无修改时显示「已保存」；语言选择下拉框
  放在状态栏右侧。
- 快捷键：`Ctrl+S` 保存活动标签（不变），新增 `Ctrl+W` 关闭活动标签；
  `Esc` 焦点移到状态栏的语言选择。
- 空态（无标签）保持现有提示，无折叠按钮。

### 其他消费点

`App.tsx`（关窗守卫 `anyDirty` + `confirmAllUnsaved`）、`TitleBar`（脏点）、
`MenuBar`（保存文件 = 活动标签脏时可用；关闭文件 = 关活动标签）、`RunToolbar`
（`entry || activeFile`；「保存并运行」按 `anyDirty`）、`WorkspacePanel`
（高亮活动文件）、`updateStatus.ts`（更新前检查改 `anyDirty`）。

## 风险与限制

- 标签无上限：极端情况下打开几百个文件会挂载几百个 CodeMirror 实例。工作区
  场景文件数量有限，暂不引入 LRU 回收；如成为问题可再淘汰最久未活动的
  非脏标签。
- 保存仍是全局单飞（一次一个），`saveAllDirty` 串行执行，并发语义与单文件
  版本一致。
- 标签顺序即打开顺序，不提供排序与持久化。
